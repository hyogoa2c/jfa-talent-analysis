# 基準カテゴリ再分類レビュー手順（2026-07-27）

対象ファイル: `data/manual/academy_reclassification_queue.csv`（84 行）
根拠: SAP v5 §1b-4（時点付き J クラブ定義）。同項は**二者レビュー**を要求しており、
自動判定＋コーディネーターの一次確認が一人目、本レビューが**二人目**にあたる。

## 0. 何を決めるレビューか

`pathway_category = j_club_academy` と付いている選手のうち、**その機関が本当に
「その選手の育成年代当時に J リーグ加盟クラブだった下部組織」か**を確認する。

`j_club_academy` は主分析の**基準カテゴリ**なので、ここに混入があると
大学・高校のオッズ比がすべてその汚染に対して測られる。外部レビューが
「限界として書くのではなく定義を直せ」とした理由がこれである。

**アウトカムは見ない。** 本レビューは曝露測定のみを対象とする。

## 1. 列の意味

| 列 | 内容 |
|---|---|
| `source_player_id` | 選手 ID（SFIX03） |
| `phase` | `phase1` = 2014–2025 標本 / `phase1b` = 1999–2025 プール標本。同一選手が両方に出ることはない（重複は除去済み） |
| `era` | phase1b のみ。`era1` = 1981–89 年生 / `era2` = 1990–99 年生 |
| `birth_year` | 生年 |
| `name_ja` | 選手名（外部ソース照合用） |
| `final_institution` | **経路ラベルの根拠になった機関**。所属クラブ欄で「最初の senior-club entry の直前にある最後の育成機関」 |
| `auto_verdict` | 自動判定の結果（§2 参照） |
| `why_flagged` | なぜキューに載ったかの日本語説明 |
| `matched_club` | 名簿で照合できたクラブの正式名。空欄 = 照合できなかった |
| `club_j_seasons` | **そのクラブが J リーグにいた期間** |
| `academy_window` | **その選手の育成年代の推定**（生年+15 〜 生年+18）。あくまで推定 |
| `academy_years_in_list` | 所属クラブ欄に記載された**実際の在籍年**。`（記載なし）` が多い |
| `infobox_youth` | **Wikipedia インフォボックスのユース欄**（`ユースクラブN` / `ユース年N`）。加盟境界 10 件は取得済み |
| `club_history` | 所属クラブ欄の全経歴（時系列。`[2種/特別指定]` はプロ入りに数えない） |
| `reviewed_category` | **記入欄** |
| `evidence_url` | **記入欄**（外部ソースを見た場合の URL） |
| `reviewer_note` | **記入欄**（判断根拠。後から第三者が検証できるように） |

**加盟境界の判定は `club_j_seasons` と在籍年を見比べる。** 在籍年は
`academy_years_in_list`（実記載）を優先し、`（記載なし）` の場合のみ `academy_window`（推定）を使う。
実年が記載されている行は自動判定でも実年を優先しているため、既に解決済みでキューに残っていない。

## 2. `auto_verdict` の種類と、期待する作業

### `j_club_boundary`（10 件）— **判断が要る**

クラブの J 加盟期間が育成年代の**一部としか重なっていない**。例:

- `19166` Y.S.C.C.横浜 / J加盟 2014-2024 / 育成年代 2013-2016
  → 4 年のうち 3 年は J クラブ。J のアカデミーとみなすか。
- `55406` 奈良クラブ / J加盟 2023-2025 / 育成年代 2022-2025
  → 4 年のうち 3 年。同上。
- `1446` 柏レイソル / J加盟 1995-2025 / 育成年代 1993-1996
  → 4 年のうち 2 年。加盟前に入団し在籍中に J 入りした型。

**推奨する考え方**: 「その選手が育成を受けた**主たる期間**にクラブが J だったか」。
迷う場合は `non_j_club_academy` 側に倒す——基準カテゴリは**汚染しないほうが安全**であり、
除外は主要 3 経路から外れるだけでラベルを捏造しないため。

### `pathway_label_error(...)`（3 件）— **判断が要る**

そもそも経路ラベル自体が誤っている疑い。3 件はいずれも既知の論点:

- `2963` / `8780`: 所属クラブ欄でユース名と提携高校名が**1 文字列に連結**されており
  （`柏レイソルU-18（千葉県立柏中央高等学校→…`）、機械判定が高校側を拾う。
  SAP §13-2 に記録した既知の弱点。一次判定は **`j_club_academy` が正しい**とした
  （SAP §1b-1 の並行所属）。
- `3242`: 散文・所属クラブ欄とも `university` を出しているのに、過去の人手レビューが
  `j_club_academy` に上書きしている。**gold も `university`**。人手レビュー側の誤りの疑い。

### `non_j_club_academy`（23 件）— **確認のみ**

名簿上 J 加盟クラブではない。三菱養和・横河武蔵野・塩釜FC・FCみやぎバルセロナ・
アミーゴス鹿児島・常総アイデンティ・エスペランサSC・FCグラシア相模原、
および海外クラブ（レアル・ソシエダ、シャルケ04、レスター、ロリアン、リーベル・プレート、
RAFAサッカーアカデミー）。**異論がなければ記入不要**。

### `institution_unknown`（48 件）— **作業不要**

所属クラブ欄から最終育成機関を特定できず、判断材料がない。
現行どおり `j_club_academy` のまま残し、SAP §13 の残存限界として報告する。
**記入不要。**

## 2b. 外部確認をどこにかけるか（優先順）

全 84 行を外部確認する必要はない。効くのは次の 3 箇所、実質 16 件である。

### (1) 名簿の加盟年 — **最優先**（3 クラブ）

`data/manual/j_league_club_registry.csv` の `j_entry_year` 列のうち、**手入力した値**。
**1 件の誤りがそのクラブの全選手に効く**ため、単価あたりの効果が最も大きい。

| クラブ | 名簿の値 | 由来 |
|---|---|---|
| 東京ヴェルディ | 1993 | 手入力 |
| 柏レイソル | 1995 | 手入力 |
| 京都サンガF.C. | 1996 | 手入力 |

> **誤りを見つけた場合はキューの行ではなく名簿を直す。** 名簿を直して
> `scripts/report_academy_reclassification.py` を再実行すれば、該当クラブの選手が
> まとめて再判定される。行単位で上書きすると、名簿の誤りが残ったまま個別に
> 打ち消すことになり、次に他の選手が同じ誤りを踏む。

Y.S.C.C.横浜 2014 / 鹿児島ユナイテッド 2016 / ヴァンラーレ八戸 2019 / 奈良クラブ 2023 は
**出場記録から導出**した値なので、確認の優先度は低い。

## 3. 記入のしかた

`reviewed_category` に次のいずれかを書く。

| 値 | 意味 | 主分析での扱い |
|---|---|---|
| `j_club_academy` | J クラブの下部組織として扱う | 基準カテゴリに**残る** |
| `non_j_club_academy` | J 加盟クラブの下部組織ではない | 主要 3 経路から**外れる**（除外・件数は報告） |
| `overseas_academy` | 海外クラブの育成組織（非J の細分。任意） | 同上 |
| `high_school` / `university` / `grassroots_club` | 経路ラベル自体を訂正する | その経路へ**移る** |
| `unknown` | 経路を確定できない | 主要 3 経路から外れる |

> **空欄の意味（重要）**: 空欄 = **`auto_verdict` に同意**。
> このリポジトリでは過去に「空欄＝確認済み」の慣行を別手順の値へ流用して事故を起こしている。
> 本キューでは **`auto_verdict` に対する同意**という意味に固定する。
> 同意できない行にだけ値を書けばよい。

**`non_j_club_academy` と書くと、その選手は主分析から外れる**（別経路へ移るのではない）。
これは SAP §1b-4 項目 3 の規定であり、汚染された基準カテゴリに残すよりは
除外して件数を報告するほうが、推定量への影響が明示的になるという判断による。

`reviewer_note` には**根拠**を書く（例: 「加盟前に入団し在籍中に J 入り。主たる育成期間は
JFL 時代のため非 J とする」）。外部ソースを見た場合は `evidence_url` に URL を残す。
後から第三者が判断を再検証できることが目的であり、SAP §6b-2 が gold に課している
「初回判定・最終判定・根拠 URL・判定者を保存する」に準じた扱いとする。

   所属クラブ欄が弱い機関名の連結も持たない。ただし採用には §1b-3 と同じ検証が要る。
